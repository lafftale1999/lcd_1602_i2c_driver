Changelog

All notable changes to this project are documented in this file. The format is based on Keep a Changelog.

[Unreleased] - 2026-10-31

Added

  • lcd_1602_write_top(): writes a string to the top row without touching the bottom row.
  • lcd_1602_write_bottom(): writes a string to the bottom row without touching the top row.
    • Both blank the rest of the row so old text is erased, stop at \0, \n or the end of the row, and return LCD_WRITE_FINISHED, LCD_TOO_LONG_STRING (truncated) or LCD_WRITE_INTERRUPTED (bus error).
  • Doxygen documentation for lcd_1602_send_char() and lcd_1602_clear_screen().
  • LCD_1602_SET_DDRAM_ADDR define to replace the magic number 0x80 used for cursor positioning.
  • CHANGELOG.md.

Fixed

  • Text overwrote the second row instead of stopping. In lcd_1602_send_string() the check row < LCD_1602_MAX_ROWS let the driver "wrap" a second time, so the third line of text was written over the bottom row. It now returns LCD_WRITE_INTERRUPTED when the text runs past the last row.
  • **A trailing \n on the bottom row was reported as an error.** "line1\nline2\n" now returns LCD_WRITE_FINISHED instead of LCD_WRITE_INTERRUPTED.
  • The headers did not compile in C++. The closing block in lcd_1602.h and lcd_i2c.h was extern "C" }, which is invalid syntax. It is now }.
  • The I2C timeout was much shorter than configured. i2c_master_transmit() takes milliseconds, but the driver passed I2C_MASTER_TIMEOUT_MS / portTICK_PERIOD_MS (ticks). With a 100 Hz tick a 1000 ms timeout became 10 ms.
  • Delays shorter than one tick did not wait at all. pdMS_TO_TICKS() rounds down, so with the default 100 Hz tick vTaskDelay(pdMS_TO_TICKS(2)) returned immediately. That broke the timing the HD44780 needs during startup and after clearing the screen. A new lcd_delay_ms() helper always waits at least the requested time.
  • The power-on delay was too short. The datasheet requires more than 40 ms after power-on, and the driver waited 15 ms (which could be under 10 ms in practice). It now waits 50 ms.
  • Errors were lost. send_command() and lcd_1602_send_char() overwrote the result of the first nibble with the result of the second, and lcd_1602_init() always returned 0. Errors are now collected and returned.
  • esp_err_t was truncated to uint8_t. Some error codes could turn into 0 (success) that way. Bus results are now compared against ESP_OK.
  • The font setting was invalid for two-row mode. The HD44780 does not support the 5x10 font with 2 display lines, so the function-set command now selects 5x8.
  • The cursor could be sent off screen. lcd_goto() now limits the column to the screen width and limits the row using LCD_1602_MAX_ROWS instead of a hard-coded 1.
  • lcd_1602_send_string() used a hard-coded 16 instead of LCD_1602_SCREEN_CHAR_WIDTH.
  • The component did not build on ESP-IDF v6. driver/i2c_master.h moved to the esp_driver_i2c component, so CMakeLists.txt now requires esp_driver_i2c instead of driver. This needs ESP-IDF v5.3 or later.
  • Doxygen fixes: wrong @file name in lcd_1602.h, stray @ in @addtogroup, and a macro reference to a define that does not exist (LCD_1602_CURSOR_MOVE_ON_WRITE).
  • README: pins are configured in project_config.h, not lcd_i2c.h. The API reference now lists every public function.

Changed

  • lcd_1602_send_string() now takes const char * (it still accepts the same arguments).
  • lcd_1602_send_string() returns LCD_WRITE_INTERRUPTED if communication on the I2C bus fails.
  • Character and command sending now share one internal write_byte() helper, which removes duplicated code.
  • lcd_1602_internal.h includes <stdbool.h> explicitly for bool.
